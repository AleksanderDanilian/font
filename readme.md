# Как устроены данные о шрифтах и как добавлять новые

У вас несколько `.json`/`.jsonl` файлов в `data/`, у которых пересекаются
поля и не всегда очевидно, что трогать руками, а что генерируется само.
Ниже — карта файлов, и пошаговый рецепт на две ситуации: добавить шрифт с
Google Fonts, и добавить платный/партнёрский шрифт не с Google.

## Карта файлов

| Файл | Кто пишет | Трогать руками? |
|---|---|---|
| `data/fonts_full_manifest.jsonl` | вы | **Да** — технические данные о шрифте (категория, поддерживаемые языки, лицензия) |
| `data/fonts.jsonl` | вы (+ опционально ИИ через `enrich_descriptions.py`) | **Да** — контентная разметка (теги настроения/индустрии, описание для поиска, premium/referral) |
| `data/tags.json` | вы | Редко — только если добавляете новую категорию тегов настроения (см. ниже) |
| `data/synonyms.json` | вы | Часто — словарь для текстового поиска, расширяется по вкусу |
| `data/fonts_metadata.json` | **скрипт** (`fetch_google_fonts_metadata.py`) | **Нет.** Чисто кэш ответа Google Fonts API. Можно удалить и перегенерировать в любой момент, руками редактировать бессмысленно — перезапишется |
| `backend/fonts.db` | **скрипт** (`build_database.py`) | **Нет никогда.** Всегда пересобирается из файлов выше |

### Почему два файла (`fonts_full_manifest.jsonl` + `fonts.jsonl`), а не один

Исторически это два независимых источника: `fonts_full_manifest.jsonl` —
технический (откуда скачан шрифт, какие языки поддерживает), `fonts.jsonl`
— контентный/кураторский (какое у него настроение, для какой индустрии).
Их можно было бы слить в один файл, но раз уже так сложилось и работает
— трогать без необходимости не будем, просто держите в голове это
разделение.

**Важный, неочевидный момент:** поле `family_name` в `fonts.jsonl` — это
на самом деле `slug` (нижний регистр, без пробелов, например `"abeezee"`,
`"playfairdisplay"`), а НЕ человекочитаемое имя. Настоящее имя
(`"ABeeZee"`, `"Playfair Display"`) лежит в `fonts_full_manifest.jsonl`
под `family_name` там же. Скрипт сборки джойнит эти два файла именно по
этому полю (нормализуя регистр) — если оно не совпадёт между файлами
буква в букву (без пробелов, в нижнем регистре) — шрифт не соберётся,
`build_database.py` покажет warning `"N записей из fonts.jsonl не нашли
пару в манифесте"`.

## Рецепт 1 — добавить шрифт с Google Fonts

1. **`data/fonts_full_manifest.jsonl`** — добавьте строку:
   ```json
   {"family_name": "Inter", "slug": "inter", "category": "SANS_SERIF", "subsets": ["latin", "latin-ext", "cyrillic"], "license": "ofl", "is_variable": true, "regular": "fonts/inter/inter-400.woff2", "bold": "fonts/inter/inter-700.woff2"}
   ```
   `regular`/`bold` тут — это только фолбэк-путь на случай, если Google
   вдруг не отдаст файл (см. `FONTS.md` → архитектура ниже); раз вы не
   раздаёте шрифты с сервера, реального файла по этому пути может и не
   быть — это нормально, шрифт всё равно найдётся через Google CDN.

2. **`data/fonts.jsonl`** — добавьте строку с `family_name`, СОВПАДАЮЩИМ
   со `slug` из шага 1 (в данном случае `"inter"`):
   ```json
   {"family_name": "inter", "mood_tags": ["modern", "minimal", "friendly"], "industry_tags": ["tech", "editorial"], "description": "A clean, no-nonsense sans that reads well on screens — a safe pick for tech products and dashboards.", "description_ru": "", "embedding": [], "is_premium": false, "referral_url": null}
   ```
   - `mood_tags` — только из существующего набора в `data/tags.json` (14 штук)
   - `description` — коротко и разговорно, 1-2 предложения, без
     типографского жаргона (см. подробный промпт-гайд в
     `backend/enrich_descriptions.py`, если делаете это через ИИ)
   - `embedding: []` — оставьте пустым, посчитается сам при сборке

3. Убедитесь, что семейство есть в `data/fonts_metadata.json` (если это
   свежедобавленный в Google Fonts шрифт — перезапросите метаданные):
   ```bash
   GOOGLE_FONTS_API_KEY=... python backend/fetch_google_fonts_metadata.py
   ```

4. Пересоберите БД:
   ```bash
   python backend/build_database.py
   ```
   В выводе будет видно, резолвнулся ли шрифт через Google CDN — если нет
   (`[warn] inter (regular): нет ни на Google...`), проверьте написание
   `family_name` в шаге 1 — должно буква в букву совпадать с тем, как
   шрифт называется на fonts.google.com.

## Рецепт 2 — добавить платный/партнёрский шрифт (не с Google)

Тут есть развилка на старте: **даёт ли партнёрская площадка публичную
ссылку на trial/preview-версию шрифта** (некоторые маркетплейсы вроде
MyFonts/Fontspring дают такую специально для встраивания превью)?

**Если да** — используйте эту ссылку напрямую как `regular`/`bold` в
шаге 1 ниже (полный `https://...` URL) — код уже умеет отдавать любую
абсолютную ссылку как есть, ровно так же, как для Google CDN, никакой
специальной обработки не нужно.

**Если нет** — оставьте `regular`/`bold` как локальные пути-заглушки.
Карточка в этом случае просто не сможет показать текст РЕАЛЬНЫМ
начертанием шрифта (fallback на обычный шрифт интерфейса) — что
разумно, раз цель карточки в этом случае — не превью, а привести
покупателя на маркетплейс через `referral_url`.

1. **`data/fonts_full_manifest.jsonl`**:
   ```json
   {"family_name": "Neue Haas Grotesk", "slug": "neuehaasgrotesk-mf", "category": "SANS_SERIF", "subsets": ["latin"], "license": "commercial", "is_variable": false, "regular": "fonts/neuehaasgrotesk-mf/regular.woff2", "bold": "fonts/neuehaasgrotesk-mf/bold.woff2"}
   ```
   `slug` тут — придумайте сами, уникальный, раз этого шрифта нет на
   Google Fonts и настоящего slug ниоткуда не взять (советую суффикс типа
   `-mf` от названия площадки, чтобы не пересечься с будущим настоящим
   Google-шрифтом с похожим именем).

2. **`data/fonts.jsonl`** — **обязательно** `is_premium: true` и реальный
   `referral_url`:
   ```json
   {"family_name": "neuehaasgrotesk-mf", "mood_tags": ["modern", "corporate", "minimal"], "industry_tags": ["fashion", "tech"], "description": "A razor-clean Swiss grotesque with real editorial pedigree — the choice when a brand wants to feel expensive and precise.", "description_ru": "", "embedding": [], "is_premium": true, "referral_url": "https://myfonts.com/fonts/...?ref=ваш_партнёрский_id"}
   ```
   Это единственное отличие от Рецепта 1 по сути: раз `referral_url`
   заполнен, ссылка на карточке будет вести именно туда (с
   `rel="sponsored nofollow"`, см. ниже), а не на Google — и badge
   "Premium" появится автоматически.

3. **НЕ добавляйте** этот шрифт в `fonts_metadata.json` — он туда и не
   попадёт сам, это файл только для настоящих Google Fonts, трогать его
   руками для премиум-шрифтов не нужно.

4. Пересоберите БД:
   ```bash
   python backend/build_database.py
   ```

## needs_review — временно скрыть шрифт без удаления

Если хотите добавить черновик записи, но пока не показывать её
пользователям (например, описание ещё не вычитано) — поставьте
`"needs_review": true` в `fonts.jsonl`. Такие записи попадают в БД, но
`FontStore` их не грузит в поиск (см. `db.py`, `WHERE needs_review = 0`).
Уберите флаг, когда будете готовы её показать, и пересоберите БД.

## Откуда берётся ссылка на карточке ("View on Google Fonts" / "Get this font")

Решается автоматически при сборке БД, ничего дополнительно указывать не
нужно:
- Если `referral_url` заполнен в `fonts.jsonl` — используется он, с
  пометкой "партнёрская ссылка" (`rel="sponsored nofollow noopener"` —
  требование Google Webmaster Guidelines для монетизируемых ссылок).
- Иначе, если шрифт найден в `fonts_metadata.json` (то есть это
  подтверждённый Google Font) — генерируется ссылка на его специмен-
  страницу `https://fonts.google.com/specimen/...` (обычная ссылка,
  `rel="noopener"`, без nofollow — она не аффилиэйт).
- Иначе — ссылки на карточке просто нет.

## Баннеры (партнёрская реклама под настройками поиска)

Логика — в `frontend/app.js`, константы `BANNERS`/`BANNER_DEFAULT`.
Каждый баннер привязан к списку тегов настроения; при нажатии Apply
выбирается первый баннер, чьи теги пересекаются с выбранными пользователем
(порядок в массиве `BANNERS` — это приоритет при пересечении нескольких),
иначе показывается баннер по умолчанию. Чтобы добавить/поменять баннер —
править только этот массив в `app.js`, отдельного файла под баннеры нет.

**Сейчас баннеры и ссылки на источник реализованы только в основном
`index.html`/`style.css`.** Остальные 6 вариантов дизайна (`index_1.html`
… `index_6.html`) их пока не показывают — дайте знать, если нужно
пропагировать на все.

## Что НЕ нужно делать

- Не редактируйте `data/fonts_metadata.json` и `backend/fonts.db` руками
  — оба на 100% генерируются, любые ручные правки исчезнут при следующей
  пересборке/перезапросе.
- Не меняйте `data/tags.json` без крайней необходимости — это фиксированная
  таксономия из 14 тегов настроения с взаимоисключающими парами (см. ТЗ,
  раздел 4.1); если добавите новый тег, придётся продумать пару-антоним
  и учесть на фронтенде (там список тегов зашит в разметку каждого
  index*.html, а не подгружается динамически по составу).
